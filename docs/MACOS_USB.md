# macOS direct USB transport and C ABI

The source starts at canonical clean-history sdr-fox
`26b6d6c728b7954391a956372012d7253271cf46` (tree
`ea8902c90b37e857be37b6dc3f7963c723bd445a`). No legacy repository, GPL source,
or SondeFox research document was consulted. macOS and Android exclude both
rusb and libusb1-sys through target dependency tables and module cfgs.
Linux/Windows keep their existing fallback behavior.

## Control OUT candidate repair

`vendor/nusb` is crates.io nusb 0.2.7, upstream
<https://github.com/kevinmehall/nusb>, crate archive SHA-256
`18ef13beb3b3a8fc16fd7aea912ebd3d45dde00a9a5b968d0742297468065845`.
It is Apache-2.0 OR MIT; both original license texts remain in that directory.
Redistribution requires preserving the chosen license and applicable notices.
Source comes from the published Cargo crate, not an unversioned branch.

Only macOS control OUT changes behavior. It uses IOKit's synchronous
`DeviceRequestTO` with owned payload/request lifetime, the caller's timeout,
a null pointer for zero-length data, and an exact-length completion check.
Control IN and bulk transfers retain upstream's asynchronous run loop.
One existing dead-code logging helper is annotated for platform-specific use.
No other nusb source changes. `scripts/test-macos-control-out.sh` makes an
isolated temporary copy and runs three deterministic request/error tests.

The prior source documented RTL2832U OUT stalls through the asynchronous
IOKit path. The current host enumerated **zero RTL-SDR and zero Airspy**.
Therefore the old physical failure was **not reproduced**, and the candidate
repair is **not hardware validated**. It must pass RTL-SDR and Airspy open,
control, sustained streaming, unplug/replug, and sleep/wake at supported rates
before direct USB acceptance can be declared complete. No speculative
successful-radio claim is made from passing mocks or compilation.

## Additive C API

`bindings/sdr_fox.h` is regenerated by the existing cbindgen 0.29.4 build.
Stable enumeration yields opaque exact-selection IDs. On macOS identity uses
VID/PID, USB topology location and serial if present; ordinary enumeration
order changes cannot redirect selection. Moving ports requires reselection.
Opening holds the native enumerated object and fails on ambiguity/disappearance;
it never re-enumerates to an index or opens another receiver.

New functions query rates and gains from the opened device, expose applied
sample rate separately from requested rate, and apply tuner gain mode,
per-stage gain/AGC, IF bandwidth and oscillator correction. Unknown capability
values stay unknown. The original C APIs remain source and ABI compatible.

Original `CU8` stream access already preserves raw RTL bytes; Airspy uses
full-rate `CF32` after its required real-to-IQ synthesis. The existing bounded
read owns any partially drained block. Coarse drop counters describe a gap,
not an exact count of missing samples. No hardware UTC is invented. Handles
remain non-recycling registry tokens, so close/cancel races retain native
storage until in-flight operations finish.
